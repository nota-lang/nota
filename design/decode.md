# Nota Decode

`decode` is the pass that turns a *flat* sequence of small content pieces into the
*nested* HTML structure a document actually wants. It does three jobs:

1. **Paragraphs** — wrap a run of inline text/elements in a `<p>`.
2. **Lists** — wrap a run of list items in a `<ul>` (`-`) or `<ol>` (`+`).
3. **Sections** — make a heading own the content beneath it, up to the next heading of
   equal-or-higher rank, inside a `<section>`.

Same idea as Pollen's `decode`, but pinned by two hard requirements: it **must run during
static site generation (SSG)**, and it **must coexist with a reactive framework** (React
or Solid) so parts of the page can re-render on the client.

The whole design hangs off one axis — **interactive vs. non-interactive content** — so we
lead with that, then build the machinery underneath it.


```
%let Colorized = component((children) => {
  let [color, setColor] = useState("red");

  - @Colorized{@x}

import { h, decode, Fragment } from "nota";

export default function Doc() {
  return decode((() => {
    let Colorized = component((children) => {
      let [color, setColor] = useState("red");
      return decode(h("span", {onClick: () => setColor("green"), style: {color}}, children));
    });
    return Fragment(["a", "b"].map(x =>
      h("nota-ul-li", {}, [
        h(Colorized, {}, x)
      ])
    ));
  })());
}

```

- h/Fragment should behave like static HTML generators by default.
- h/Fragment should call into the appropriate framework (react, solid's hyperscript) when invoked under the call stack of a `component(...)` call.
- decode should do pollen-style decode for static HTML generated by nota, stopping at component boundaries.
- decode inside component should do nothing, I think?
- Nota HTML gen and decoding happens completely by the end of SSG, no runtime behavior.
- Framework then hydrates individual islands using its normal hydration approach.

## Algorithm

The whole thing turns on one piece of dynamic state — a flag `▸` ("are we executing inside
a component body?"). Every context-sensitive primitive branches on it, and that single flag is
what makes the bullets above fall out.

### Data model
```
vnode v ::= string                       // text leaf
          | ⟨t, p, k⟩                     // t = tag, p = props, k = child vnodes
t       ::= "div" | "nota-ul-li" | …           // host string  → static, decode owns it
          | CompFn                        // component fn → boundary, framework owns it
```
A static build yields a tree of plain `⟨t,p,k⟩` (the stage-4 tree). Component-tagged nodes are
*deferred*: `h(Colorized, …)` does not call `Colorized`, it just records a boundary.

### Context-sensitive primitives
`h`/`Fragment` build inert nota vnodes by default, but switch to framework hyperscript under `▸`;
`decode` is the SSG pass by default, a no-op under `▸` (inside a component every `h` already
returned an opaque framework element — nothing for a restructuring pass to see, and the framework
owns that subtree's render *and* reactivity).
```
h(t,p,…k):       ▸ ? Framework.h(t,p,flatten(k)) : ⟨t,p,flatten(k)⟩   // component tags NOT invoked
Fragment(k):     ▸ ? Framework.Fragment(k)        : ⟨FRAG,{},flatten(k)⟩
decode(v):       ▸ ? v                            : serialize(struct(v))

inlineComponent(fn) / blockComponent(fn):
  marked       = (props) => withFlag(▸=true, () => fn(props.children, props))
  marked.isComp= true;  marked.kind = "inline" | "block"             // kind drives <p> grouping
  return marked
```

> **Amended by contract R18 (doc-state).** At `▸=false`, `decode` is `serialize ∘ struct ∘ force ∘
> index ∘ normalize`, not just `serialize ∘ struct`: `normalize` (R10 expansion + fragment splicing,
> hoisted to a whole-tree pre-pass), then `index` (collect `mark` leaves into a `DocIndex`), then
> `force` (resolve `query` leaves against that index) all run **before** `struct`/grouping. `#` sugar
> re-lowers to the ambient `Heading` slot (`h(Heading, {rank})`), which emits a `mark` + a `query`
> producing the concrete `<hN>` — forced before grouping, so `groupSections` below still sees a real
> heading. See `contract.md` §0 R18.

### Structural pass — `struct` (vnode → vnode)
Three sibling-grouping jobs over a child list, in this order (lists/headings must survive paragraph
grouping; sections must see the lists/paras they own), then recurse — *stopping at boundaries*.
```
struct(v):
  if v is string:    return v
  if v.tag is a PLAIN function (not isComp):                          // R10: a static template —
      return struct(splice(v.tag({children: v.children, …v.props})))  // invoke + splice its output
                                                                      // into the sibling stream
                                                                      // BEFORE grouping (sentinels
                                                                      // coalesce with siblings')
  if isComp(v.tag):  return ⟨v.tag, v.props, map(struct, v.children)⟩  // decode static CHILDREN,
                                                                       // do NOT descend into body
  k = groupSections(groupParas(groupLists(v.children)))
  return ⟨v.tag, v.props, map(struct, k)⟩                             // recurse into new host nodes

groupLists(k):     // coalesce a same-kind sentinel run → one list
  scan k; a maximal run of identical `nota-ul-li`/`nota-ol-li` → ⟨ul|ol, {}, [⟨li,{},itemᵢ.children⟩…]⟩.
  "Maximal" bridges interior whitespace (R16): a whitespace-only text run *immediately followed by a
  same-kind sentinel* is consumed (blank lines between items don't split the list); anything else
  ends the run and its trailing whitespace is left in place (edge whitespace preserved for groupParas).
  Nested lists need no case: the parser nests a deeper run inside the parent item's children,
  so struct's recursion forms the inner list.

groupParas(k):     // maximal inline run → <p>; blank-line markers split; block siblings pass
  isBlock(v) = ⟨t,…⟩ ∧ ( t ∈ HOST_BLOCK_TAGS ∨ (isComp(t) ∧ t.kind=="block") )
  inline components join the run (land inside the <p>); block components flush it and pass through.

groupSections(k):  // a heading owns following siblings until the next heading of rank ≤ its own
  ⟨section, {}, [heading, …groupSections(owned)]⟩;  recurse so deeper headings nest.
```

### Serialize + islands

> **Superseded in part by contract R15 (replay hydration).** The *server* side below stands, with
> one correction: the manifest is now **debug metadata only** — `manifest[id] = { comp }`, no
> props. The client does NOT "read the manifest to hydrate": it **replays the document** —
> re-executes `render(Doc)` with `island()` in a capture mode that records each live boundary
> (component with closure intact, live props, recomputed slot; ids match the server by
> construction), then hydrates each `[data-hydration-id]` marker (`hydrateDocument(Doc)`). This is
> what lets an island be defined at any depth, close over document state (`@for` variables), and
> take non-JSON props (functions). See `contract.md` §0 R15 + §8.

`struct`'s output has only boundary `CompFn` nodes left. Serialization stringifies host nodes and
renders each boundary as a hydration island:
```
serialize(v):
  v is string  → escape(v)
  isComp(v.tag)→ island(v)
  else         → `<t …attrs>` + map(serialize,v.children).join("") + `</t>`

island(v):
  id   = freshId()                                   // hydration-id counter
  slot = map(serialize, v.children).join("")         // static children → pre-rendered HTML slot
  manifest[id] = { comp: nameOf(v.tag), props: v.props }            // client reads this to hydrate
  return withFlag(▸=true,                                           // flips context for the body
    Framework.renderToString(Framework.h(v.tag, {…v.props, "hydration-id": id}, raw(slot))))
```
Inside `renderToString` the body runs with `▸=true`: its `h`→`Framework.h`, its `decode`→identity,
and `useState("red")` bakes `style="color: red"` into the SSR'd `<span>`.

### SSG driver
```
SSG(file):
  Doc = compile(file).default                  // emitted module (stage-3 code)
  reset(▸=false, ids=0, manifest={})
  html = serialize(struct( Doc() ))            // Doc() = stage-4 tree; struct+serialize = `decode`
  write(file.html, shell(html))
  write(file.json, manifest)                   // island manifest → client hydrate(id) per island
```
Mapping to the arrows above: `Doc()` is the stage-4 tree (statics built, components deferred);
`struct` then `serialize` together are the single `decode(…)` call collapsing stage 4 → stage 5.
Everything runs at build; the client re-runs the *document* once (the R15 replay — HTML discarded,
islands captured) and then only island bodies stay live.

### Component slots
A boundary's *children* were authored outside the component, so they are static nota vnodes:
`struct` decodes them (lists/paras in `@Aside{…}` still group), but stops at the component's own
body. `island` then feeds the decoded children to the framework as a pre-serialized raw HTML slot.
